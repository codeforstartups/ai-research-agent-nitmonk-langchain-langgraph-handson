# Internal Note: Risks and Moats for a New Entrant (illustrative)

> Sample/synthetic data for the course.

## Key risks

- **Platform risk**: incumbents who own the editor or code host can bundle a
  "good enough" agent for free, compressing standalone pricing.
- **Model commoditisation**: if capability comes mostly from a foundation model,
  a thin wrapper has no defensible moat.
- **Reliability ceiling**: autonomous agents that fail silently erode trust
  fast; a single bad production change can end an enterprise pilot.
- **Support burden**: enterprise deals demand security reviews, custom
  deployment, and hand-holding that strain small teams.

## Possible moats

- **Vertical depth**: specialising in a domain (e.g. data pipelines, embedded,
  a specific legacy stack) where general tools are weak.
- **Proprietary evaluation & reliability tooling**: the ability to *prove* the
  agent is trustworthy is itself a product.
- **Workflow lock-in via governance**: audit, policy, and review integrations
  that become part of the customer's compliance posture.
- **Context engineering**: superior grounding in the customer's codebase and
  institutional knowledge.

## Strategic read

Entering "as another coding agent" is a losing position. Entering as
"the reliable, governable coding agent for regulated enterprises" is a
defensible wedge — but only with real investment in evaluation, observability,
and human-in-the-loop control.
